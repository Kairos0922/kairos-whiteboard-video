# 渲染内核设计（kernel.py v1，2026-08-26）

> 面向对象：未来维护/扩展内核的技术负责人会话。读完能知道每个决策为什么这么定、
> 哪里能改、改了会炸哪里。上游为 MIT 项目 [whiteboard-video-engine](https://github.com/gnipbao/whiteboard-video-engine)。
> 定位：本层是 `whiteboard-video-principles.md` P1（增量揭示）与 §3（模型管终态、引擎管过程）
> 的实现层。认知决策不在本层——内核只负责把已定的揭示顺序画出来。

## 1. 选型决策

### 六种笔迹方案对比（2026-08-26 调研结论）

| 方案 | 笔尖贴线 | 主要代价 | 我们的态度 |
|---|---|---|---|
| 整图逐块显露 | 弱 | 块状感、假连线 | 否决（质量不可接受） |
| 对象分割 | 中 | 分割与遮挡成本 | v1 不做，路线图 |
| SVG 路径 | 强 | 素材需矢量、填色另做 | 不做（板图是位图） |
| 中心线骨架 | 强 | 噪点/粗色块碎笔 | **采用**（v1 主路线） |
| 程序化图元 | 强 | 复杂角色成本高 | 不做（角色来自模型） |
| 视频模型 | 不稳定 | 一致性/重试成本 | 不做（本地确定性红线） |

### 采用混合方案的理由

- 宿主文生图模型负责整幕板图；本地程序负责分区、路径、时序、合成；
  两层各干各的，返工范围可控（见 §4 重跑矩阵）；
- 数学底座**复用上游引擎**而非重写：MIT 许可、纯函数 API、算法与教程同源
  （Zhang-Suen 细化、八邻接追踪、分叉直行优先、端点切向合并），按 commit 锁定
  （pyproject `rev`），升级需跑全量测试再换 rev；
  **2026-09-13 已升 rev**（`3155215` → `86848ea`，锁点后 7 提交：story 管线、
  豆包词级时间、字幕烧录、风格系统）。兼容性三验全过：本仓库依赖面仅 5 符号
  （`preprocess` 的 trace_8connected / zhang_suen_skeleton / Stroke /
  merge_nearby_strokes + `whiteboard._open_ffmpeg_rawvideo_writer`）签名未变、
  函数体未动（改动全是文件尾追加）、依赖零增；全量 77 测试绿。新 rev 顺带
  解锁三个路线图参照入口（只登记，吸收另立项）：
  文字描字 `whiteboard.py:534 _text_to_strokes` / `:571 _text_wipe_strokes`（第 1 项）、
  对象成组 `preprocess.py:617 group_strokes_into_blocks` + `StrokeBlock`（第 3 项）、
  词级→短语 cue→全局进度 `tts.py:214 _word_phrase_cues` / `whiteboard.py:1601
  _narration_paced_time`（P2 编译层对照组；上游是全局 0→1 进度，本内核仍是
  分区/对象时间窗，差异保持）；
- 时间调度层**自研**：上游整幕渲染无「按旁白窗口分区揭示」，而这正是
  「视觉不领先于认知」（principles P3 / `script-design.md` §1 第 4 条）的技术落点，是我们的差异化核心。

## 2. 数据流与模块

```
boards-layout/scene-XX.png ─┐
annotations/scene-XX.json ──┼→ kernel.render_region_scene → build/scenes/scene-XX.mp4
assets/hand-pen-*.png ──────┘        │
   load_board_layers：板图 → (RGB, 墨迹掩码, 骨架)          一次性提取防重复 IO
   _trace_merged：骨架 → 追踪 → 切向合并 → 笔画点列
   assign_element：笔画质心 → 最小包含矩形元素（无归属=丢弃，防串区）
   build_fill_strokes：色块蛇形扫描线（排除骨架膨胀区）
   build_tasks：绝对时间任务表（draw/travel，L 比例时长）
   渲染循环：canvas 增量上墨 + 手部贴笔尖 → ffmpeg rawvideo → H.264
```

## 3. 关键设计决策（含踩坑记录）

1. **底色自适应判墨**：`|px-背景中位色|` 三通道距离阈值。纸面找暗线、深板找亮线
   同一套代码；背景取四边 8px 带中位色，不信任单侧。
2. **分区归属用质心落点**：骨架笔画质心落入哪个元素矩形就归谁；矩形嵌套取最小面积；
   落不进任何矩形直接丢弃。代价是贴边元素可能丢笔画，换来的是绝不串区。
3. **描线与填色分离**：填色候选 = 色距超标 **且不在骨架 3px 膨胀区内**。
   教训（2026-08-26 冒烟）：不排除骨架区时，暗线被当成待填色块，layout 全画布
   元素产生 32 条假填色路径冲爆时间窗。
4. **时长按弧长 L 比例分配**：元素窗口内 usable 时长按各笔画长度归一化，
   下限（MIN_STROKE_MS）放不下时退回纯比例，窗口永不溢出。
5. **抬笔预算精确制**：间隙预算 = duration/4 上限；预算耗尽或单处间隙 <40ms
   就不产生 travel 帧（直接落笔）。教训（同日冒烟）：40ms 下限托底 × 32 处间隙
   = 1280ms 超窗，元素间时间串门。
6. **收尾整图兜底**：全部 draw 结束后整板图呈现一小段（COMPLETE_TAIL_MS），
   骨架细化/行距扫描漏掉的零星像素最终不出戏。
7. **手部锚点**：HAND_TIP_RATIO 是手素材的笔尖像素比例，**换手素材必须重新校准**，
   错了表现为笔尖悬浮或笔杆插进纸里。
8. **子槽时长 √弧长权重**（2026-09-11）：对象组的描线槽/填色槽间按 √(槽总弧长)
   分配窗口（`_slot_durations`），填色蛇形路径总弧长 ∝ 面积，线性比例下大色块
   霸窗、轮廓一闪而过；√ 压缩后轮廓多分、铺色收快（细描慢、铺色快）。
   √ 必须作用在**槽级总量**——若下沉到笔画级再求和（Σ√），多条短笔画会虚增
   权重，语义就变了（测试 SlotDurationTest 首版夹具踩中过）。槽内笔画间仍按
   线性弧长保持恒定笔速。参照 whiteboard-animator（Kinoslide）的 √面积组件级
   权重，见 §5 参照实现。

## 4. 重跑矩阵（input / build / deliverables 三层职责）

> **唯一权威口径是 `engine-design.md` §8**，本表只是它在渲染层的子集速查。
> 两处不一致时一律以 engine-design 为准，改口径只改那一处。

| 改了什么 | 重新生成 | 可保留 |
|---|---|---|
| 口播含义或时长 | 配音→时长表→标注→受影响幕 | 角色图、手素材、主题包 |
| 某一幕板图 | 该幕标注+渲染 | 脚本、配音、其他幕 |
| 某个绘制区（改 annotation） | 该幕渲染 | 板图、其他幕 |
| 手部素材 | 受影响幕渲染 | 板图、脚本、配音 |
| 字幕样式 | assemble | 全部场景视频 |
| 主题风格块 | 板图起全链 | 脚本、表达设计卡 |

state.json phases + 两次确认（script_audio / boards_reviewed）是系统能判断
「哪些结果还能用」的唯一依据，改动后手工重置对应 phase。

## 5. v1 边界与路线图

> 2026-09-03 定级变化：`ir-alignment.md` §5 选了方案 A（panel 重定义为「揭示单元」），
> 所以下面第 2、3 项（`protectedRegions` 真实生效、对象级编排）**从可选优化升为必做前置**，
> 排期见 `ir-alignment.md` §8 第 4 步。

当前不支持（按优先级）：
1. **文字逐笔描字**：中文标题按字形轮廓描边再填色（上游有 _text_to_strokes 可借鉴）；
2. **多边形区域**：annotation 目前只消费矩形，异形构图靠矩形并集近似；
3. **对象级编排**：按对象（而非区域）排序笔画，遮挡关系更自然；
4. ~~validate 终检层~~ **已实现**（`whiteboard_story/validate.py`，见 engine-design §7）；
5. **蛇形行距自适应**：按区域色块密度调 FILL_ROW_STEP；
6. **`HIGHLIGHT` 原语**（表达层需求，`expression-plan.md` §5）：对已绘制区域加框或加深，
   不改动其结构。实现前只能用 `GROUP`（加框）近似；
7. **元素级 `REMOVE`**：按分区/对象掩码减墨（板擦笔迹）。**内核当前只会加墨不会减墨**，
   所以"擦除、删冗余"这类认知变化目前只能改写成前后态并排；实现后 `COUNTEREXAMPLE` 才能直画；
8. **视口操作 `REFRAME`**（平移 / 局部放大）：当前是固定画布逐步上墨，无视口概念；
   实现前表达层禁止该操作，需要换尺度一律切成新 Scene。

第 6–8 项是**目标机指令集缺口**：`expression-plan.md` §5 的合法性检查依赖本表，
内核能力扩张后再逐项解禁（改一处表即可，别在计划里偷跑）。

### 参照实现与反例警示：whiteboard-animator（Kinoslide，MIT）

> 2026-09-11 评估结论：**不换底座，按项吸收**。
> 仓库 https://github.com/masihsultani/whiteboard-animator （浅克隆于 /tmp，临时），
> 关键决策以下表为准，不在代码里引它做依赖。
> 全方向扫描（10 项目 + 矢量路线 + 语音对齐粒度光谱 + 手部方案汇总）见
> [survey-whiteboard-render-engines.md](survey-whiteboard-render-engines.md)；
> 其 §12 的吸收清单是对本节的增补供货，逐项落地时按本节格式登记。

可借鉴（精华）：
- **√面积/弧长时间权重**：组件级时间槽随 √面积 缩放，大填色不霸占时间线。
  **已吸收**（§3 第 8 条，`_slot_durations` 槽级 √ 弧长）；
- **组件排序启发式**（component_ordering.py）：容器先于内容、形状先于标签、
  文字阅读顺序、小点附着所属字形、并查集空间分组。**做第 3 项对象级编排时的
  首选参照**；本内核 v2 的 `_object_groups` 已有连通域分组 + 阅读顺序，
  缺"容器先于内容"的包含关系与深度排序；
- **骨架分叉分解**（skeleton_paths.py）：分叉点分支配对、X/网格分解为顺序
  笔路径、环形单独提取。分叉线稿出"从中间长出"问题时参照；
- **填充双模式**：轮廓描一圈后，大块斜向扫掠、小块鬃毛刷笔触，S 曲线切换。
  观感优于单一蛇形，但与本内核"揭示即原图成形"的刷宽复制策略取舍不同，
  仅在蛇形填色观感被二审否决时再评估；
- **流式增量提交**：完成像素只提交一次、仅渐隐像素逐帧混合。渲染提速时参照。

不可引（糟粕，对本项目为硬伤）：
- **白底硬编码**：`gray < 240` 判墨，深色板整个被当墨迹逐块"画满"（chalk 探针
  图实测复现，2026-09-11）。本内核的底色自适应判墨是正确路线；
- **MAX_DIM=1280 强制降采样**：1080p 输入出 720p 成片，不满足 1920×1080 交付；
- **无词级语音对齐**：节奏从文本估算，违反 P2/P3——这是本项目的差异化核心；
- **83MB CRAFT 文字检测 + 逐词书写**：与"板图不带文字"铁律冲突，仅当版式层
  未来做"标签逐字写入"动画时再回看（本仓库 review_images 的文字检测是启发式，
  定位相反：拦截文字而非书写文字）；
- **无手部跟随**（其官方 roadmap 求助项）：本内核已有手素材 + tip 锚点方案。
